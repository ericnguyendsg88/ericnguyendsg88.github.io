Requirements case study

AI monitoring MVP for a payments-infrastructure client

Anonymised. Client details are removed, and the wording is rewritten.

Summary

The client wanted AI to watch high-value settlement: project each participant's liquidity during the day, and catch unusual transaction behaviour. There was no fixed scope, no production data and no final infrastructure design. I turned that into an MVP the client, developers and data scientists could all test against.

My role

  • Ran requirements workshops with the client's product and engineering teams.
  • Kept the requirements register linked to the functional spec by ID.
  • Wrote the user stories and UAT test cases, and a data guideline for the critical datasets.

How I scoped it

  • Two use cases, in order. Liquidity projection first, anomaly detection second.
  • Batch, not real-time. Real-time processing went on a "won't have" list the client signed.
  • Advisory only. Nothing the system produces triggers a settlement or funding action.
  • Five anomaly types. Detection was narrowed to the highest-priority patterns, each with a UAT scenario.

Example requirement

LIQ-03 · Must

Flag a participant when their projected worst case breaches the threshold.

Accepted when every monitored participant gets a worst-case value each batch, and every breach raises a flag with the reason.
